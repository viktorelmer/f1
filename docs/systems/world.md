# Пак контента, доменная модель и генератор мира (M1)

Разделы 4.2, 5.11 и 10 плана. Мир фиксированный: стартовое состояние берётся из пака без участия сида. Сид определяет только скрытые величины и всё, что случится после старта.

## Пак (`src/data/packs/default/`)

Формат пака публичный: любой пак проходит через одну функцию `parsePack(files)`, построенную на схемах Zod (`src/data/schema/`). Типы контента выводятся из схем (`z.output`), так что расхождения между схемой и типом не бывает. Весь текст в паке — латиница (решение владельца), без полей перевода.

| Файл | Содержимое |
|---|---|
| `manifest.json` | id, версия, версия формата, стартовая дата карьеры, лицензия, атрибуция |
| `tracks.json` | 22 трассы: название, длина, круги, эталонное время, потеря на пит-стопе, профиль (10 параметров 4.2), погодный профиль, заводской сетап (9 параметров 5.2) |
| `geometry.json` | для каждой трассы: SVG-путь в поле 1000×1000 от линии старта по направлению гонки, границы 3 секторов и DRS-зоны как доли длины круга, въезд и выезд с пит-лейна. Мини-сектора симуляция нарезает сама по длине пути. Файл генерируется `npm run pack:geometry` |
| `teams.json` | 11 команд: цвета, база, история (титулы, победы, места за 3 последних сезона), мотор (заводской или клиентский), рейтинги 7 узлов шасси, уровни 8 зданий, департаменты, финансы, спонсоры, репутация по 5 осям, ожидания владельцев, характер ИИ, диапазоны скрытых величин |
| `drivers.json` | 22 боевых пилота и 40 резервистов (11 штатных резервистов и 29 свободных агентов): атрибуты, личность, состояние, дата рождения, контракт (или его отсутствие), диапазоны скрытых величин |
| `staff.json` | по 16 человек на команду (роли из 5.5 и 5.19) и пул свободных специалистов |
| `engine-suppliers.json` | 4 поставщика: заводская команда, характеристики силовой установки, цена поставки |
| `regulations.json`, `calendars.json` | регламент стартового сезона (очки, потолок, ATR по местам, лимиты компонентов, формат уик-энда); 22 этапа с датами, 6 из них спринтовые |
| `new-team.json` | условия режима B: взнос FIA, депозит, арендуемые мощности, стартовый штат с оговорёнными зарплатами (у свободных агентов в паке контракта и зарплаты нет) |

**Кросс-проверки** схемы, помимо формы полей: id уникальны, ссылки ведут на существующие сущности, в каждой команде ровно 2 боевых пилота и по одному человеку на каждую роль, в календаре существующие трассы и возрастающие даты, диапазоны скрытых величин не пустые и лежат в допустимых границах.

**Геометрия** импортируется из открытого набора bacinger/f1-circuits (MIT) скриптом `scripts/import-track-geometry.ts`. Скрипт делает проекцию, упрощение и нормализацию и выставляет точку старта и направление движения. Настройки лежат в конфиге скрипта для каждой трассы. Атрибуция — в поле `attribution` манифеста пака. Названия трасс вымышленные, геометрия реальная (раздел 2 плана).

## Доменная модель (`src/sim/types/`)

Динамическое состояние (`World`) отделено от статического контента. Трассы, геометрия и регламенты по годам живут в паке, а сейв хранит ссылку на пак (id + версия). Типы 4.2 дописаны полностью. Описаны и сущности из списка плана: `Team`, `Staff`, `Facility`, `Department`, `RnDProject`, `CarPart`, `Setup`, `Sponsor`, `Contract`, `Regulation`, `Season`, `RaceWeekend`, `SessionResult`, `NewsItem`, `SocialPost`, `Rival`, `SaveGame`. Те из них, чьи системы появятся позже, в M1 представлены типами и пустыми коллекциями, а уточнять их будут вехи этих систем.

```ts
type World = {
  schemaVersion: 1; seed: string; pack: { id: string; version: string };
  date: GameDate; season: SeasonState;
  career: CareerState;                         // режим, команда игрока, делегирование, ожидания владельцев
  teams: Record<TeamId, Team>; drivers: Record<DriverId, Driver>;
  staff: Record<StaffId, Staff>; engineSuppliers: Record<EngineSupplierId, EngineSupplier>;
  hidden: { drivers: Record<DriverId, DriverHidden>; teams: Record<TeamId, TeamHidden> };
  knowledge: Record<TeamId, TeamKnowledge>;    // оценки (Estimate) каждой команды
  news: NewsItem[]; social: SocialPost[]; projects: RnDProject[];
};
```

**Отличие от черновика 4.2:** скрытые величины вынесены из `Driver.hidden` в общий `world.hidden`. Всё, что зависит от сида, живёт ровно в двух поддеревьях: `hidden` (правда) и `knowledge` (оценки). Отсюда два следствия. Проекция мира для интерфейса — это мир без `hidden`, и правда не может утечь по построению. А проверка DoD «видимое одинаково, скрытое разное» становится точной.

**Характеристики болида** (`CarPerformance`, 4.2) вычисляются чистой функцией из рейтингов узлов шасси и силовой установки поставщика. Веса «узел → характеристика» лежат в `car.json`. Узлы — единственный источник правды: разработка в M6 будет менять узлы, а характеристики пересчитываться сами. Калибровка весов — задача M2.

## `createWorld(seed, pack, career)`

1. **Детерминированная часть** строится без ГСЧ: команды, пилоты, персонал, контракты, финансы, календарь в `GameDate`, болиды.
2. **Режим A** (`{ mode: 'takeover', teamId }`): игрок возглавляет одну из 11 команд, ожидания владельцев берутся из пака. Остальные 10 команд — ИИ.
3. **Режим B** (`{ mode: 'founder', name, shortName, colours, baseCountry, engineSupplierId, driverIds }`): игрок основывает 12-ю команду, в сетке 24 болида.
   - Сразу списываются взнос и депозит.
   - Мощности арендованы (уровень 0), мотор клиентский и на поколение хуже — штраф из баланса.
   - Первые 2 сезона нет исторических призовых, репутация начинается с нуля.
   - Штат стартовый, из `new-team.json`, поэтому часть областей делегирования недоступна.
   - Пилоты — двое из свободных агентов; `createWorld` отвергает занятых.
   - Цели владельцев: выжить, набрать очки к 3-му сезону, войти в топ-5 к 6-му.
4. **Сид**:
   - скрытые величины каждого пилота и каждой команды, включая новую, берутся из диапазонов пака по потокам `world:hidden:*`. Распределение треугольное (сумма двух равномерных): крайние значения диапазона реже средних;
   - первичные оценки потенциала всеми командами (см. estimate.md). Своих пилотов команда знает точнее (коэффициент в балансе), а команда без скаута не знает о потенциале ничего сверх общедоступного: уверенность 0.
5. **Акцент интерфейса** — основной цвет команды игрока из пака или из выбора в режиме B. `applyAccent()` вызывает интерфейс при старте карьеры в более поздней вехе.

`checkWorld(world, pack)` — чистая функция, которая возвращает список нарушенных инвариантов: ссылки, составы, границы, отсутствие правды в оценках. Это и есть критерий «валидный мир» из DoD. Полная Zod-схема мира нужна для сейвов и появится в M12.

## Баланс (`src/data/balance/*.json`)

Каждое значение записывается как `{ "value": …, "why": "…" }`. Загрузчик на Zod проверяет, что комментарий есть у каждого листа, и отдаёт системам обычные числа. В M1 файлы такие: `estimate.json`, `decide.json`, `car.json` (веса узлов), `career.json` (параметры режима B: стартовые деньги, отставание клиентского мотора, сезоны без наследственных призовых).

## Чего нет в M1

- Интерфейса нет: мир пока не показывается.
- Первый слайс Zustand и перевод верхней панели с моковых данных на состояние — в M2, вместе с воркером. Мир будет жить там, а в UI приходить снимком без `hidden`.
- Скрытый идеальный сетап трасс появится с системой сетапа.

## Тесты (DoD)

- `createWorld` в обоих режимах возвращает мир, в котором `checkWorld` не находит нарушений.
- При разных сидах мир без `seed`, `hidden` и `knowledge` совпадает побайтово, а `hidden` различается.
- При одном сиде результат совпадает побайтово (хеш).
- Схемы отвергают битые данные: нет поля, значение вне диапазона, висячая ссылка, дубль id, три боевых пилота в команде, пустой диапазон скрытой величины.
- Режим A и режим B покрыты отдельными наборами тестов.
- Добавление пилота в пак не меняет скрытые величины остальных.
