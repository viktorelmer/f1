# Каркас приложения и дизайн-система (M0)

Веха M0 не содержит игровых систем: ни ГСЧ, ни `Estimate<T>`, ни `decide()` здесь нет — они появляются в M1. Этот документ фиксирует то, на чём будут стоять все следующие вехи: слои и их защиту, игровое время, дизайн-токены, примитивы, навигацию и i18n.

## Слои и их защита

`sim ← app ← ui`, как в разделе 3.2. Алиас `@/` указывает на `src/`. Правила чистоты проверяются дважды:

- хук Claude Code `.claude/hooks/check-sim-purity.sh` — при каждой правке агентом;
- ESLint — для любого редактора и будущего CI: в `src/sim/` запрещены импорты `react*`, `@/app/*`, `@/ui/*`, глобалы `Date` и `performance`, `Math.random`, `crypto.getRandomValues/randomUUID`; в `src/app/` запрещены импорты `@/ui/*`. Тесты и бенчмарки освобождены от запрета на время. Правило само покрыто тестом: ESLint прогоняется на фикстуре с нарушениями.

## Игровое время: `GameDate`

`GameDate` — целое число дней от 1970-01-01 по пролептическому григорианскому календарю, брендированный `number`. Преобразование в `{ year, month, day }` и обратно — целочисленный алгоритм days-from-civil (Hinnant), без JS `Date`. Прибавить день — `d + 1`, сравнить даты — `<`. День недели — `(d + 4) mod 7`.

Почему не «день от старта сезона»: такая дата не отображается без якоря в состоянии, а якорь сезона меняется каждый год. Почему не строка ISO: сравнение и арифметика дороже, а в сейве это ничего не даёт. Эпоха 1970 выбрана потому, что это родная эпоха алгоритма, и в тестах результат можно сверить с `Date.UTC` на диапазоне 1900–2200 (тестам `Date` разрешён).

Код: `src/sim/types/game-date.ts`. Решение дублируется в ADR 001.

## Токены и тема

Тема одна — тёмная. Токены — CSS-переменные в пространстве имён Tailwind v4 (`@theme` в `src/ui/design/tokens.css`), так что утилиты получаются короткими: `bg-panel`, `text-lo`, `border-line`, `bg-tyre-soft`. Стандартная палитра Tailwind отключена (`--color-*: initial`): цвета вне токенов в разметке просто не существуют. Тема объявлена как `@theme static`, поэтому в CSS попадают все переменные, даже не использованные ни одним классом: SVG, графики и inline-стили читают токены через `var()`, а Tailwind таких мест не видит. Цветовой токен не может называться так же, как размер текста: `text-base` стал бы неоднозначным, поэтому фон называется `ground`, а не `base` (это нашлось при проверке в браузере).

| Токен | Значение | Роль |
|---|---|---|
| `ground` / `panel` / `raised` | `#0C0F14` / `#141922` / `#1C2330` | фон, панели, приподнятые элементы |
| `line` / `line-strong` | `#2A3341` / `#3A4557` | разделители, рамки при наведении |
| `hi` / `lo` | `#E8EDF5` / `#8593A8` | основной и вторичный текст |
| `accent` / `accent-fg` | задаётся при старте карьеры | цвет команды игрока и текст на нём |
| `positive` / `negative` | `#34D399` / `#F04E4E` | выигрыш и потеря |
| `tyre-*` | soft, medium, hard, inter, wet — из 6.1 | компаунды |

`accent-fg` вычисляется из `accent` по контрасту WCAG (светлый или тёмный), потому что команда может быть и жёлтой, и тёмно-синей. До старта карьеры акцент нейтральный. Кольцо фокуса рисуется цветом `hi`, а не акцентом: тёмно-синий акцент на тёмном фоне фокус не покажет.

Сетка — 4 px (шаг spacing в Tailwind v4 по умолчанию), строка таблицы — 28 px. Размеры текста: 11 / 12 / 13 / 14 / 16 / 20 px, основной — 14, в таблицах — 13. Скругление маленькое (2–4 px) и только там, где оно что-то значит.

**Шрифты** подключаются локально через Fontsource: игра офлайновая, CDN ей не нужен. Интерфейс — Roboto Condensed Variable: из кандидатов плана кириллица есть только у него, у Barlow Condensed и Archivo Narrow её нет. Числа — JetBrains Mono Variable, у него есть кириллица, и все цифры одной ширины. Все времена, разрывы и бюджеты в интерфейсе набираются моноширинным.

## Примитивы (`src/ui/design/`)

- **Button** — варианты `primary` (акцент), `secondary`, `ghost`, `danger`; размеры `sm` и `md`.
- **Panel** — заголовок с необязательными действиями и тело; плоская, с рамкой `line`.
- **Table** — описывается колонками (`key`, заголовок, выравнивание, `numeric`); строка 28 px, заголовок липкий. Числовые колонки выравниваются вправо и набираются моноширинным.
- **Tooltip** и **Dialog** — поверх Radix: фокус, клавиатура и ARIA оттуда, внешний вид наш.

Компонент `Estimate` в M0 не делаем: он опирается на тип из M1.

## Оболочка и навигация

Раскладка из 6.2: верхняя панель (дата · следующее событие · бюджет · позиция в КК · «Продолжить»), слева 8 разделов, у каждого раздела строка вкладок. Данные верхней панели в M0 моковые, «Продолжить» неактивна. Каждая вкладка ведёт на пустой экран с заголовком.

Роутинг — TanStack Router с файловыми маршрутами в `src/ui/routes/`. Файлы маршрутов тонкие: подключают экран из `src/ui/screens/`. Каждый будущий экран получает свой файл, свою загрузку данных и отдельный чанк. `routeTree.gen.ts` коммитится, чтобы `tsc` работал без запуска Vite. URL на английском: `/hq/overview`, `/car/development`, `/weekend/race`. Разделы и вкладки перечислены один раз, в `src/ui/navigation.ts`, откуда их берут меню и вкладки. Тест проверяет, что у каждого пункта меню есть маршрут и каждый маршрут открывается.

Демо-страница `/dev/components` показывает все примитивы, палитру, шрифты и переключатель акцента.

## i18n

i18next + react-i18next. Словари лежат в `src/i18n/locales/{ru,en}.json`, ключи типизированы: опечатка в ключе — ошибка компиляции. Русские формы множественного числа берутся из `Intl.PluralRules` (суффиксы `_one` / `_few` / `_many`). Язык определяется так: сохранённый выбор, если он есть, иначе язык браузера `ru*` → ru, иначе en. Переключатель — внизу бокового меню. Тест следит, чтобы наборы ключей в ru и en совпадали.

## Чего нет в M0 и почему

- Zustand + Immer, Comlink, Dexie, Zod, D3, Recharts, Motion ставятся в тех вехах, где у них появляется работа (M1–M3). Пустые слайсы и неиспользуемые зависимости только мешают.
- `npm run sim:batch` подключён как точка входа (`scripts/sim-batch.ts`), но пока честно завершается с ошибкой «нет систем для прогона» — первая система появится в M2.
- Папки из 3.2 создаются сразу, пустые — с `.gitkeep`.

## Проверка DoD

- «Приложение запускается»: `npm run build` проходит, плюс запуск dev-сервера и скриншот из браузера.
- «По всем разделам можно ходить»: тест навигации по всем 8 разделам и всем вкладкам, плюс ручной проход в браузере.
- «3 примера компонентов на демо-странице»: `/dev/components` и тесты примитивов (Dialog открывается и закрывается с клавиатуры, Tooltip показывается по фокусу, Table выравнивает числа).
