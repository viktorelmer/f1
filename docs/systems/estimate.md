# Оценки: `Estimate<T>`, `observe()`, `refine()` (M1)

Раздел 4.1 плана. Всё, что игрок видит с неопределённостью, — это `Estimate`. Правда живёт в состоянии мира, оценка получается из неё только через наблюдение.

## Тип

```ts
type Estimate<T extends number = number> = {
  value: T; low: T; high: T;       // для показа, в границах величины
  confidence: number;              // 0..1 → подпись «низкая / средняя / высокая»
  sources: ObservationSource[];    // что сузит интервал (подсказка 6.6)
  observedAt: GameDate;
  basis: { mean: number; sd: number; min: number; max: number; wideSd: number };
};
```

`basis` — модель наблюдателя: среднее и разброс его измерений, границы величины и ширина, при которой оценка считается «ничего не знаю». В `basis` попадают только результаты измерений, правды там нет. Этого поля нет в черновике плана. Оно нужно, чтобы `refine()` работала с исходной моделью, а не с обрезанным по границам `value`.

`T` ограничен числами: у интервала должен быть порядок. Вероятность дождя, позиция на финише или потенциал — всё это числа.

## Наблюдение и точность

```ts
type Precision = { sd: number; bias: number };  // разброс и смещение, в единицах величины
measure(truth, precision, rng, at): Observation          // value = truth + bias + N(0, sd)
observe(truth, precision, rng, { quantity, at, sources }): Estimate
refine(prior: Estimate, observation: Observation): Estimate
```

- **Разброс** (`sd`) вычисляет вызывающая система из качества наблюдателя: скаута, отдела анализа, симулятора. Кривые «навык → sd» лежат в балансе.
- **Смещение** (`bias`) приходит из скрытых величин мира, например корреляции аэротрубы. В `Estimate` его нет ни в каком виде, и интерфейс его никогда не показывает.
- **Интервал**: `mean ± z · sd`, обрезанный по границам величины. `z` задаёт номинальную вероятность попадания в интервал (80%).
- **Уверенность**: `clamp(1 − sd / wideSd, 0, 1)`. Пороги подписей лежат в балансе.
- **`refine`** объединяет прежнюю оценку и новое наблюдение с весами, обратными дисперсиям, как два гауссовых измерения. Интервал только сужается. Смещение так не убрать: серия наблюдений из одного смещённого источника даёт узкий уверенный интервал вокруг `truth + bias`. Это ровно тот «уверенный и неправильный» случай, который описывает 4.1. Расширение интервала при конфликте источников в M1 не делаем, это вопрос к M6.

## Когда вычисляется

Оценки вычисляются в определённые моменты и сохраняются в состоянии, при отрисовке их не пересчитывают. В M1 такой момент один — создание мира. Каждая команда, и игрок, и соперники, получает свою оценку потенциала каждого пилота в `world.knowledge[teamId]`. Разброс зависит от навыка её скаута. ИИ принимает решения по своим оценкам, а не по правде (5.10: «ИИ не читерит»).

## Константы (`src/data/balance/estimate.json`)

`z` интервала, пороги подписей уверенности, спецификация величины `driver.potential` (границы и `wideSd`), кривая «навык скаута → sd» для потенциала.

## Тесты

- Структурный: в оценке нет правды и нет смещения. Проверяется по ключам объекта и по тому, что при `sd > 0` `value ≠ truth`.
- При `sd → 0` и `bias = 0` оценка стремится к правде.
- `refine` сужает интервал и сходится к `truth + bias`. Со смещением правда в итоге выпадает из интервала.
- Одинаковые сид и вход дают одинаковую оценку.
- Интервал не выходит за границы величины.

Компонент показа оценки (6.6) в M1 не делаем: в этой вехе нет экранов. Он появится вместе с первым экраном, где есть оценки.
