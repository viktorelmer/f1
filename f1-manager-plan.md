# F1 Manager — план разработки

Документ-задание для ИИ-агента. Версия 0.1 (этап планирования).
Проект: браузерная менеджерская игра про руководителя команды Формулы-1.
Референс глубины: Capitalism Lab, Football Manager. Референс визуала: телевизионная графика F1 и командные пит-стенды.

## 0. Как агенту работать с этим документом

**Правила, которые действуют на всех этапах:**

1. Работать строго по вехам (M0 → M12). Не начинать следующую веху, пока текущая не проходит свой Definition of Done.
2. Ядро симуляции (`src/sim/`) — чистый TypeScript без React, без `Date.now()`, без `Math.random()`. Только переданный сид и переданное время. Это правило нарушать нельзя ни при каких обстоятельствах: на нём держатся тесты, воспроизводимость и балансировка.
3. Каждая веха завершается: тестами (Vitest), коротким `docs/adr/NNN-*.md` с принятыми решениями, и обновлением `docs/CHANGELOG.md`.
4. Числовые константы (баланс) не хардкодятся в коде логики — только в `src/data/balance/*.json` с комментариями к каждому значению.
5. Контент (трассы, команды, пилоты, детали болида) — данные, а не код. Загружается из JSON-паков, чтобы игрок мог подменить их своими.
6. Перед реализацией крупной системы агент пишет короткий design-note (0.5–1 страница) в `docs/systems/` и только потом код.
7. Каждый экран UI сначала существует с моковыми данными, потом подключается к состоянию.
8. Каждая система, где игрок принимает решение, реализуется через контракт `decide()` (раздел 5.19) — так делегаты игрока и ИИ соперников используют один код. Отдельной логики «для ИИ» быть не должно.
9. Всё, что игрок видит с неопределённостью, представляется типом `Estimate<T>` (раздел 4.1) и отображается одним компонентом интерфейса (6.6). Собственных вариантов «примерного значения» в отдельных системах быть не должно.

**Формат постановки задачи агенту:**
> Реализуй веху M4 из `f1-manager-plan.md`. Соблюдай правила из раздела 0. Начни с design-note по системе стратегии гонки, затем модель, затем тесты, затем UI. В конце — краткий отчёт, что сделано и какие решения приняты.

## 1. Видение и опоры дизайна

Игрок — руководитель команды (Team Principal). Он не ведёт болид, он принимает решения, которые превращаются в результат через людей, деньги, технику и репутацию.

Пять опор, к которым сверяется каждая фича:

1. **Каждая цифра имеет причину.** Пилот проиграл 0.3 с на круге — игрок может докопаться, из чего сложились эти 0.3: сетап, износ шин, температура, форма пилота, аэродинамика на этом типе поворотов.
2. **Долгие циклы важнее коротких.** Решение о направлении разработки болида в марте отзывается в сентябре. Контракт с пилотом на три года — реальное обязательство.
3. **Ограниченность — главный источник интереса.** Бюджетный потолок, лимит времени в аэротрубе (ATR), лимит компонентов ДВС, кадры, календарь. Всё, что игрок хочет, стоит чего-то другого.
4. **Гонка — кульминация, а не мини-игра.** Её нужно смотреть и в неё нужно вмешиваться, но выигрывается она в основном заранее.
5. **Медиа — полноценный ресурс.** Репутация влияет на спонсоров, спонсоры на бюджет, бюджет на болид. Слова тоже имеют цену.

**Чего в игре нет:** 3D, рендер гонки от камеры, аркадного вождения, микротранзакций, онлайна (в v1).

### 3.3 Детерминизм

- Один сид на партию. От него порождаются именованные подпотоки: `rng('race:2027:monza:incidents')`, `rng('market:2027:driver-moves')`. Так добавление новой системы не сдвигает случайность в старых.
- Симуляция гонки — чистая функция `simulateRace(input: RaceInput): RaceResult`, где `RaceInput` включает сид. Одинаковый вход → побайтово одинаковый выход.
- Отсюда бесплатно получаются: реплеи (сохраняем только вход), тесты, батч-прогон 1000 сезонов для балансировки, будущий мультиплеер.

### 3.4 Модель времени

Две шкалы:

- **Межгоночная**: тик = 1 день. Игрок обычно жмёт «продолжить» и проматывает до следующего события. События: завершение проекта разработки, переговоры, дедлайны, новости.
- **Гоночный уик-энд**: сессии по кругам, внутри круга — сегменты (сектора, 3 на круг, опционально мини-сектора для точности). Игрок смотрит в реальном времени с ускорением ×1 / ×2 / ×5 / ×15, может паузить и вмешиваться.

## 4. Доменная модель (черновик типов)

### 4.1 Оценки и неопределённость — обязательный примитив

Почти каждая система игры показывает игроку не факт, а **оценку**: интервал темпа соперника, прогноз погоды, ожидаемый прирост от R&D-проекта, диапазон рекомендаций инженера по сетапу, потенциал молодого пилота, остаточный ресурс мотора, требования агента на переговорах, прогноз финиша по ходу гонки.

Это одна и та же механика в разных костюмах, и реализована она должна быть один раз. Иначе агент напишет пять разных вариантов и нарисует пять разных способов их отображения, а игроку придётся учить пять визуальных языков вместо одного.

```ts
type Estimate<T = number> = {
  value: T;          // наиболее вероятное значение
  low: T;            // нижняя граница интервала
  high: T;           // верхняя граница
  confidence: number;// 0..1, для дискретной подписи и сортировки
  sources: ObservationSource[]; // что сузит интервал: симулятор, практика, скаут, аналитика
  observedAt: GameDate;
};
```

**Истинное значение никогда не попадает в `Estimate`.** Правда живёт в состоянии мира, оценка порождается из неё функцией наблюдения:

```ts
observe<T>(truth: T, precision: Precision, rng: Rng): Estimate<T>
```

Так утечка правды в интерфейс становится невозможной по построению, а не по договорённости.

**Точность состоит из двух независимых частей**, и это важно:

- **Разброс** — ширина интервала. Слабый отдел просто знает меньше.
- **Смещение** — систематическая ошибка в одну сторону. Плохая корреляция аэротрубы делает команду стабильно оптимистичной: детали всегда работают хуже расчёта. Смещение опаснее разброса, потому что его не видно изнутри, и оно проявляется только при столкновении с реальностью — на предсезонных тестах или в первом же прогоне на трассе.

**Уточнение по мере поступления данных:**

```ts
refine<T>(prior: Estimate<T>, observation: Observation<T>): Estimate<T>
```

Длинная серия в FP2 сужает оценку деградации шин. Три сессии наблюдения за соперником сужают оценку его темпа. Год работы с пилотом сужает оценку его потенциала.

**Требование детерминизма.** Оценки вычисляются в определённые моменты (конец сессии, тик дня, завершение этапа R&D) и **сохраняются в состоянии**. Пересчёт на каждую отрисовку запрещён — иначе интервалы будут дрожать при перерисовке и ломать воспроизводимость. `Estimate` сериализуется в сейв как есть.

## 5. Игровые системы

### 5.1 Болид и разработка

**Компоненты болида** — 6–8 узлов, каждый со своим уровнем и вкладом в характеристики: переднее крыло, заднее крыло, днище, боковые понтоны и охлаждение, подвеска, тормоза, коробка, силовая установка (поставляется, если команда не заводская).

**Ресурсы разработки:**
- Время в аэротрубе и объём CFD — лимит зависит от места в Кубке конструкторов (чем выше, тем меньше). Классическая механика «догоняющего преимущества».
- Деньги в рамках бюджетного потолка.
- Ёмкость дизайн-офиса (люди × их качество).

**Цикл разработки одной детали:**
`Концепт → Исследование (открывает потолок улучшения) → Проектирование → Производство → Установка на болид → Валидация на трассе`

Ключевая механика — **неопределённость**. Проект показывает *ожидаемый* прирост с доверительным интервалом. Ширина интервала сужается качеством аэродинамиков, симулятора и объёмом потраченного ATR. На трассе деталь может отработать хуже расчёта (корреляция аэротрубы и реальности — отдельный параметр фабрики). Это делает работу симулятора и качество инженеров осмысленными.

**Философия болида.** Игрок задаёт направление сезона: «низкое сопротивление», «максимальный прижим», «стабильность на торможении». Направление даёт бонус к профильным проектам и штраф к остальным. Смена философии в середине сезона стоит дорого.

**Разработка следующего года** параллельна текущей и делит те же ресурсы — центральный стратегический выбор всей игры.

### 5.2 Сетап

**Девять параметров, разделённых на три уровня доступа.** Все девять существуют в модели с самого начала и все влияют на время круга. Разница в том, какие из них команда способна осмысленно настраивать.

| Уровень | Параметры | Компромисс |
|---|---|---|
| **База** | Угол переднего крыла | Поворачиваемость на входе ↔ износ передних шин |
| | Угол заднего крыла | Прижим и тяга на выходе ↔ скорость на прямых |
| | Распределение тормозов | Стабильность на торможении ↔ блокировка колёс |
| **Механика** | Клиренс спереди | Работа днища ↔ риск пробоев и порпойзинга |
| | Клиренс сзади | Прижим на быстрых поворотах ↔ сопротивление |
| | Жёсткость подвески | Механическое сцепление ↔ поведение на поребриках |
| **Тонкая настройка** | Развал колёс | Сцепление в повороте ↔ износ и нагрев |
| | Схождение | Стабильность на торможении ↔ температура шин |
| | Передаточные числа | Ускорение ↔ максимальная скорость |

**Условия доступа — возможности команды, а не опыт игрока:**

- **Механика**: гоночный инженер ≥ 60 **или** симулятор 2-го уровня. Достижимо для любой команды через целенаправленное вложение — это выбор приоритета, а не стена.
- **Тонкая настройка**: инженер ≥ 78 **и** симулятор 3-го уровня **и** пилот с `feedback` ≥ 65. Привилегия зрелой команды.

Деление проходит не по важности, а по сложности. Параметры базы монотонны: направление компромисса очевидно. Параметры третьего уровня взаимозависимы (эффект развала меняется в зависимости от клиренса) и имеют узкое немонотонное окно — вслепую их крутить хуже, чем не трогать. Это и есть внутриигровое объяснение блокировки.

**Экспертный режим.** В настройках игры блокировка снимается принудительно. Параметр становится доступен, но инженер по нему молчит: ни рекомендации диапазона, ни обратной связи от пилота. Риск в обмен на свободу.

**Как работает цикл.** У каждой трассы есть скрытый идеальный сетап, смещающийся от температуры воздуха, температуры асфальта, ветра и осадков. Игрок его не видит. Гоночный инженер выдаёт рекомендацию диапазоном («переднее крыло 22–31»), ширина диапазона зависит от:

- качества гоночного инженера,
- уровня симулятора на фабрике,
- атрибута `feedback` пилота,
- объёма данных, собранных на этой трассе ранее.

Свободные заезды сужают диапазон: пилот проезжает серию кругов и возвращается с описанием поведения — «не поворачивает на входе», «срывается задняя ось на выходе», «жрёт передние шины». Описание указывает направление коррекции, но не точное значение.

Отклонение от идеала даёт две вещи: потерю времени на круге (нелинейно, с плато у оптимума) и характер поведения, который тянется в гонку — сетап под квалификацию убивает шины в гонке.

**Автосетап — четыре источника, в порядке приоритета:**

1. Сохранённый пресет игрока для этой трассы. Помечается как устаревающий: болид за год изменился, точность прошлогодних значений падает пропорционально объёму внесённых в машину изменений.
2. Рекомендация инженера — середина текущего диапазона по открытым параметрам.
3. Заводской пресет трассы из пака. На нём всегда стоят все закрытые параметры.
4. Копирование сетапа напарника.

Заводской пресет подобран прилично, но не идеально: 0.05–0.15 с потери в зависимости от трассы. На Спа и в Сузуке дорого, в Монако почти неважно.

**Балансировка:** полное владение третьим уровнем даёт 0.1–0.15 с на круге. Заметно в борьбе за поул, не смертельно для того, кто до него не добрался. Проверяется батч-прогоном на M6: команда с закрытым третьим уровнем не должна терять больше одной позиции в среднем по сезону при прочих равных.

Эта система оправдывает существование сразу трёх других: инженерного состава, вложений в симулятор и атрибута пилота `feedback`. Без неё они висят в воздухе.

### 5.3 Уик-энд и свободные заезды

Практики — не разминка, а единственный механизм превращения времени и шин в информацию. Всё, что игрок узнаёт про сетап, деградацию шин, реальный эффект апгрейда и темп соперников, добывается здесь.

**Программы прогонов.** Сессия — это очередь программ, каждая занимает круги и комплект шин:

| Программа | Что даёт | Чем платим |
|---|---|---|
| Работа над сетапом | Сужает диапазоны рекомендаций инженера | Круги, шины |
| Длинная серия | Модель деградации компаундов на этой трассе, топливный расчёт | Много кругов, комплект «в мусор» |
| Симуляция квалификации | Проверка сетапа на пределе, уверенность пилота | Свежий мягкий комплект |
| Оценка апгрейда | Подтверждает или опровергает расчётный прирост детали | Круги, риск обнаружить провал |
| Аэродинамические замеры | Данные корреляции для фабрики (см. 5.12) | Медленные круги, потерянное время |
| Калибровка топлива | Точность расхода на круге | Круги |
| Выезд новичка | Обязателен дважды за сезон в FP1; опыт молодому пилоту | Потерянная сессия основного пилота |

**Ограничители.** 60 минут на сессию (реальное время сессии, а не круги — трафик и красные флаги съедают его безвозвратно). Ограниченный запас шин на весь уик-энд, часть комплектов обязательна к возврату после каждой сессии. Риск аварии: разбитый в FP3 болид — это деньги из бюджетного потолка, испорченный апгрейд и старт из боксов.

**Основной конфликт**, который система обязана порождать: отдать FP2 длинной серии и приехать в квалификацию с сырым сетапом, либо наоборот — стартовать высоко и не понимать, как поедут шины в гонке.

**Выбор комплектов шин** делается заранее, до уик-энда, вслепую по отношению к погоде. Распределение по трём сухим компаундам фиксируется в заявке. Ошибка в прогнозе означает, что в воскресенье не на чем ехать.

**Квалификация.** Q1/Q2/Q3 с вылетом по пять. Решения: момент выезда (трасса резинится, последние круги быстрее — но риск не успеть или попасть под красный флаг), трафик, использование слипстрима напарника, число попыток против запаса шин, режим мотора.

**Спринтовый формат** на части этапов: одна практика, спринт-квалификация, спринт, основная квалификация, гонка. Меньше времени на настройку, выше цена ошибки в пятницу.

**Гонка.** См. 5.4.

### 5.4 Симуляция гонки

**Модель времени круга** (базовая формула, агент калибрует коэффициенты на M2):

```
lapTime =
    track.baseLapTime
  * (1 + carDelta)          // из CarPerformance, взвешенной профилем трассы
  * (1 + driverDelta)       // pace, форма, усталость, мораль
  * (1 + setupDelta)
  * (1 + tyreDelta)         // компаунд, износ, температура, окно работы
  * (1 + weatherDelta)
  * (1 - trackEvolution)
  + fuelPenalty             // ~0.03 с на кг
  + trafficPenalty          // грязный воздух впереди идущего
  - drsGain - ersGain - slipstreamGain
  + noise(driver.consistency, rng)
```

**Шины.** Три сухих компаунда + промежуточные + дождевые. У каждого: базовый грип, скорость деградации, «обрыв» (cliff) после порога износа, окно рабочих температур, скорость прогрева. Деградация зависит от стиля пилота, `tyreManagement` болида, абразивности трассы, температуры, топливной загрузки.

**Обгоны.** Позиционная модель: считаем разрыв, при разрыве < 1.0 с в зоне DRS — попытка. Вероятность успеха от: дельты скорости, `overtakingDifficulty` трассы, `racecraft` атакующего против защищающегося, разницы в состоянии шин, агрессивности (задаётся игроком по радио). Неудачная попытка стоит времени обоим и греет шины. Есть шанс контакта, растущий с агрессией.

**События:** сейфти-кар, VSC, красный флаг, поломки (по компонентам, с деградацией ресурса ДВС через сезон), проколы, ошибки пилота (вероятность растёт от усталости, давления, дождя), штрафы (5 с, drive-through, стоп-энд-гоу), расследования стюардов.

**Пит-стопы.** Время = база + качество пит-крю + усталость механиков + случайность (провал колеса, залипший разъём). Игрок выбирает круг и компаунд, может делать undercut/overcut. Стратег ИИ предлагает варианты и показывает прогноз финиша, если поехать сейчас против «остаться в круге».

**Погода** — пять независимых величин, каждая со своим эффектом. Это отдельная система, а не флаг «дождь/сухо»:

| Величина | На что влияет |
|---|---|
| Температура воздуха | Мощность мотора, охлаждение, выносливость пилота |
| Температура асфальта | Окно работы шин, скорость деградации. Расходится с воздухом на 10–25° и меняется за 15 минут при смене облачности |
| Влажность | Мощность, скорость прогрева резины, риск конденсата на трассе утром |
| Ветер: скорость и **направление** | Меняет поведение болида в конкретных поворотах: встречный на торможении добавляет стабильность, попутный на входе в быстрый поворот отбирает её |
| Осадки: интенсивность и покрытие | Смена резины, видимость, аквапланирование. Приходит по секторам |

Ветер — самая важная из них с точки зрения геймплея. Смена направления между субботой и воскресеньем обесценивает часть работы по сетапу и заставляет игрока решать: перенастраивать болид под парк-ферме нельзя, значит, придётся ехать так.

**Прогноз** имеет точность, зависящую от качества метеослужбы. Слабая команда видит «вероятность дождя 40% во второй половине гонки», сильная — «дождь придёт между 31 и 36 кругом, сначала в третьем секторе». Решение о переходе на промежуточную резину должно оставаться решением игрока, а не автоматикой.

**Эволюция трассы.** Асфальт покрывается резиной, сцепление растёт, времена падают. Пятничное утро на «зелёной» трассе может быть на 1.5–2.5 с медленнее воскресного круга — зависит от `trackEvolution` в профиле трассы (уличные трассы эволюционируют сильнее всего).

Следствия, ради которых система и нужна:

- выезжать в конце сессии выгоднее, чем в начале — отсюда осмысленный выбор момента в Q3;
- первые круги FP1 почти бесполезны для замеров темпа, но нужны для сбора данных;
- дождь смывает резину и откатывает трассу к исходному состоянию;
- у стартовой решётки есть чистая и грязная сторона: нечётные позиции стартуют по накатанной траектории, чётные теряют на старте. Учитывается при выборе стратегии на квалификацию;
- гоночная траектория «резинится» отдельно от остальной ширины трассы, поэтому обгон вне траектории стоит сцепления.

**Радио.** Во время гонки игрок отдаёт указания: темп (push / нейтрально / беречь шины / беречь топливо), режим ERS, агрессия в борьбе, командные приказы, менять план на N-стоповый. Пилот может отказаться выполнять приказ — по морали, эго и ситуации.

### 5.5 Люди

**Гонщики.** Развитие по возрасту с кривой (пик 26–32), скрытый потенциал раскрывается лишь косвенно (через скаутинг и работу). Форма и мораль реагируют на результаты, обещания руководителя, паритет с напарником, публичные высказывания. Внутрикомандное соперничество — отдельный конфликтный контур.

**Персонал.** Технический директор, главный аэродинамик, руководители департаментов, гоночные инженеры (по одному на пилота), стратег, главный механик, пит-крю, метеоролог, скаут, глава маркетинга. У каждого — атрибуты, зарплата, контракт, репутация, амбиции. Соперники их переманивают.

**Рынок.** Межсезонье и окно во время сезона. Переговоры с пилотами и агентами: зарплата, бонусы за очки/подиум/титул, статус первого номера, отступные, срок, опции продления. Интерес пилота зависит от перспектив команды, репутации руководителя, денег, наличия места в топ-команде. Академия молодых пилотов, аренда в другие команды.

### 5.6 Инфраструктура и департаменты

Здания и их уровни: аэротруба, вычислительный кластер (CFD), симулятор, цех композитов, стенд ДВС, тренажёрный/медцентр, штаб-квартира, маркетинговый отдел. Постройка занимает месяцы и не считается в бюджетный потолок (как и в реальном регламенте) — важная стратегическая лазейка.

Каждый департамент имеет численность, качество, мораль и загрузку. Перегруженный отдел делает работу дольше и хуже.

### 5.7 Финансы

Доходы: призовые за место в КК, «наследственные» бонусы, титульный спонсор, спонсоры по позициям на болиде (боковина, антикрыло, воздухозаборник, комбинезон, кепка), плата пилотов-рентодателей, мерч, стоимость поставки моторов клиентам.

Расходы: зарплаты (не входят в потолок для топ-3 сотрудников и пилотов — важный нюанс), разработка, производство, логистика, штрафы, аварийный ремонт.

**Бюджетный потолок** — жёсткий. Превышение → расследование FIA → штраф деньгами, срезание ATR или снятие очков. Игрок видит прогноз расходов до конца сезона и должен балансировать: авария в Монако — это не только очки, это ещё и дыра в бюджете.

**Спонсоры** имеют KPI: «финишировать в топ-6 не менее 8 раз», «набрать 500 тыс. подписчиков», «обеспечить N упоминаний в прессе». Выполнение даёт бонус, провал — потерю партнёра.

### 5.8 Медиа и соцсети

- **Пресс-конференции и интервью.** Выбор ответа из вариантов с разными последствиями: защитить пилота (мораль ↑, отношения с FIA ↓), обвинить соперника (фанбаза ↑, риск скандала), уйти от ответа (нейтрально, скучно, интерес прессы ↓).
- **Репутация** по осям: у болельщиков, у пилотов и персонала (влияет на найм), у FIA, у спонсоров, у прессы.
- **Соцсети.** Аккаунт команды с подписчиками и вовлечённостью. Контент-план: посты о технике, мемы, закулисье, продвижение спонсоров, реакция на события. Кампании стоят денег и времени маркетингового отдела. Растущая фанбаза → выше цена спонсорских пакетов.
- **Кризисы.** Утечка, конфликт пилотов, обвинение в нарушении регламента, неудачное высказывание. Требуют реакции в течение нескольких дней.
- **Живая новостная лента** генерируется симуляцией: результаты, слухи о трансферах, комментарии соперников, аналитика темпа. Слухи могут быть ложными.

### 5.9 Регламент и эры

Регламент — объект в данных: технические ограничения, распределение ATR, система очков, бюджет, состав уик-энда, лимит компонентов. Меняется по годам, изредка — крупная реформа, которая обнуляет часть наработок и перетасовывает расстановку сил. FIA публикует изменения заранее, давая игроку время подготовиться — или проигнорировать и поплатиться.

### 5.10 ИИ соперников

10 команд ИИ, каждая со своим «характером»: агрессивная в разработке, консервативная, ориентированная на молодых пилотов, богатая и неэффективная. ИИ управляет теми же системами, что и игрок, через упрощённые эвристики + скоринг вариантов. Обязательное требование: ИИ не читерит с ресурсами. Сложность настраивается компетентностью ИИ, а не бонусами к характеристикам.

### 5.11 Режимы старта карьеры

**Режим A — возглавить команду.** Игрок выбирает одну из 11 существующих команд. Каждая идёт со своей историей, инфраструктурой, контрактами, долгами, ожиданиями владельцев и своим набором проблем. Топ-команда — это давление и обязанность выигрывать; аутсайдер — свобода и нехватка всего. Ожидания владельцев задаются при старте и определяют, за что игрока уволят.

**Режим B — основать команду.** Полноценная сложная игра, а не косметическая опция. Отличия:

- вступительный взнос FIA и обязательный депозит,
- нет фабрики: аэротруба, симулятор и цех строятся с нуля, первый сезон проходит на арендованных мощностях,
- только клиентские моторы, на поколение хуже заводских,
- нет исторических призовых первые два сезона — доход только от спонсоров и позиции в КК,
- репутация команды на нуле: приличные пилоты и инженеры не идут, доступны новички, ветераны на закате и рентодатели,
- зато полная свобода: имя, цвета, база, структура, философия с чистого листа.

Владельцы в этом режиме требуют не результата, а выживания: не обанкротиться, набрать очки к третьему сезону, войти в топ-5 к шестому.

Балансируется отдельно от режима A и тестируется отдельным батч-прогоном.

### 5.12 Ресурс компонентов и плановые штрафы

Лимит на сезон по каждому элементу силовой установки: ДВС, турбина, МГУ-H, МГУ-K, батарея, электроника, выхлоп. Плюс лимит коробок передач. Превышение — штраф на стартовой решётке.

Каждый компонент имеет остаточный ресурс, который тратится пробегом и ускоренно — агрессивными режимами мотора. Игрок видит износ и решает: беречь мотор в квалификации, потеряв позиции, или выжать всё и приблизить замену.

Отсюда возникает лучшее плановое решение в игре: **взять штраф осознанно**. Поставить свежий комплект на трассе, где обгонять легко, стартовать пятнадцатым и приехать пятым — вместо того чтобы дотягивать умирающий мотор до конца сезона и терять по 15 л.с. на каждом этапе. Игра должна показывать прогноз ресурса до конца сезона, чтобы это решение можно было планировать за пять этапов.

### 5.13 Разведка соперников и достоверность данных

Времена соперников в практике **не являются информацией**. Все ездят с разным запасом топлива, в разных режимах мотора и на разных стадиях программы. Отдел анализа данных приводит наблюдаемые времена к сопоставимому виду, но с погрешностью.

Игрок никогда не видит «Скудерия быстрее на 0.20». Он видит: «быстрее на 0.10–0.45 с, уверенность средняя». Ширина интервала зависит от качества отдела анализа и от объёма собранных наблюдений. К воскресенью интервал сужается.

Соперники могут **скрывать темп намеренно** — ездить с перегрузом топлива в пятницу. ИИ-команды с соответствующим характером делают это регулярно. Игрок тоже может: не показывать реальный темп, чтобы соперники неверно построили стратегию.

Так пятница перестаёт быть формальностью и становится разведкой. И так вложения в отдел анализа данных получают смысл.

### 5.14 Паддочная политика

Слой, почти отсутствующий в играх жанра, и при этом одна из главных механик реальной Формулы-1.

- **Голосования по регламенту.** Комиссия принимает изменения на будущие сезоны. У каждой команды свой интерес: тем, кто вложился в определённую концепцию, выгодно её сохранить. Игрок голосует, ведёт переговоры, торгуется поддержкой.
- **Технические директивы.** FIA может посреди сезона уточнить трактовку правила и запретить чью-то концепцию. Если игрок построил болид вокруг решения, которое запретили, часть разработки сгорает. Предупреждение приходит заранее, но нечёткое.
- **Протесты.** Подать жалобу на болид соперника: подозрительно гибкое крыло, спорная система охлаждения. Успех бьёт по темпу конкурента, провал стоит репутации в паддоке и портит отношения. Соперники протестуют против игрока по той же логике.
- **Отношения** с FIA, промоутером, поставщиком моторов и другими командами — числовые, влияют на исход голосований, на строгость стюардов к пилотам игрока и на условия поставок.

### 5.15 Переток знаний и переманивание

Наём инженера у соперника приносит не только его атрибуты, но и **понимание чужой технической концепции** — временный бонус к профильным R&D-проектам. Цена: садовый отпуск от 6 до 12 месяцев, в течение которых человек получает зарплату и не работает.

Обратная сторона: уход ключевого аэродинамика к сопернику отбирает знания у игрока. Удержание сотрудников — активная задача, а не пассивный расход.

Редкое событие: обвинение в промышленном шпионаже, если переток знаний оказался слишком буквальным. Расследование, штраф, потенциальное исключение из чемпионата.

### 5.16 Время людей как ресурс

**Пилот** между этапами распределяет ограниченный бюджет времени: работа в симуляторе (данные для сетапа и разработки), физподготовка (выносливость, устойчивость к перегрузкам), спонсорские мероприятия (обязательны по контракту, влияют на доход), отдых (восстановление, снижение усталости). Перегруженный пилот чаще ошибается в гонке.

**Резервный пилот** во время уик-энда работает в симуляторе на базе, помогая с сетапом в реальном времени. Ещё одно применение простаивающего актива.

**Персонал** устаёт от календаря. Трипл-хедеры и дальние выезды копят усталость: растёт время пит-стопов, чаще случаются ошибки в боксах и сборочные дефекты. Ротация состава на выездах — решение, у которого есть цена в качестве работы.

### 5.17 Предсезонные тесты

Три дня с жёстким лимитом пробега перед началом сезона. Единственный момент, когда выясняется, соответствует ли зимняя работа расчётам аэротрубы.

Игрок распределяет дни между пилотами и программами: набор километража для надёжности, замеры корреляции, отработка сетапов, пит-стоп-тренировки. Результат теста показывает **реальные** характеристики болида против ожидаемых — и если корреляция подвела, менять что-то уже поздно.

Отдельно: тесты на прошлогодних болидах для молодых пилотов (не считаются в лимит) и обкатка новых членов пит-крю.

### 5.18 Здоровье и форма пилотов

Болезнь перед этапом, травма после аварии, перегрев в жарких гонках, усталость шеи на трассах с высокими перегрузками. Тяжёлая авария выводит пилота на несколько этапов.

Резервный пилот перестаёт быть строчкой в списке: его нужно держать в готовности, платить ему и следить за тем, чтобы он не ушёл. Спортивный доктор и медцентр на базе сокращают сроки восстановления.

### 5.19 Делегирование

Систем в игре достаточно много, чтобы вручную вести все сразу стало невозможно. Слой делегирования решает это, **не отнимая контроль**: любую область можно вести самому в любой момент, ничего не блокируется и не упрощается.

**Три режима на каждую область:**

| Режим | Кто решает | Когда уместен |
|---|---|---|
| Вручную | Игрок, полностью | Область, которая интересна игроку или критична сейчас |
| По указанию | Игрок задаёт намерение, сотрудник прорабатывает детали | Основной режим для большинства областей |
| На усмотрение | Сотрудник, игрок получает отчёт | Периферия, рутина, области без сильного персонала |

**Почему делегат хуже игрока.** Не компетенцией — по своей специальности хороший сотрудник игроку не уступает и выдаёт 90–97% от достижимого результата. Он проигрывает в **понимании контекста**: оптимизирует под задачу по умолчанию и не знает, что именно на этой гонке нужна позиция на старте любой ценой, потому что обгонять здесь негде. Ручное управление выигрывает в нестандартных ситуациях и не выигрывает почти ничего в рутинных. Это и есть искомый баланс.

Слабый сотрудник проигрывает иначе — не средним результатом, а **разбросом**. Его решения непредсказуемы, и иногда он ошибается заметно.

**Три правила, обязательные к соблюдению:**

1. **Делегирование меняет, кто решает, но не то, что видит игрок.** Ни в одном режиме информация не скрывается. Все данные, интервалы и обоснования доступны всегда.
2. **Любое решение перехватывается.** Где позволяет время — делегат предлагает, игрок подтверждает или правит. Во время гонки доступен режим «предлагать с паузой»: игра останавливается в момент решения стратега.
3. **Переключение в любой момент, в обе стороны, без штрафов и таймеров.**

**Области и делегаты:**

| Область | Кто ведёт | Что задаётся указанием |
|---|---|---|
| Сетап | Гоночный инженер | Приоритет: квалификация / гонка / сохранность шин |
| Программы практик | Спортивный директор | Что важнее собрать за уик-энд |
| Стратегия гонки | Стратег | Уровень риска, целевая позиция |
| Радио в гонке | Гоночный инженер | Агрессия, режим экономии |
| Портфель разработки | Технический директор | Философия, распределение между текущим и следующим годом |
| Наём персонала | Операционный директор | Бюджет, приоритетные департаменты |
| Соцсети и контент | Глава маркетинга | Тон, приоритет спонсорских активаций |
| Спонсорские переговоры | Коммерческий директор | Минимальные условия |
| Скаутинг и академия | Скаут | Профиль искомого пилота, регионы |
| Тренировки пилотов | Тренер | Баланс подготовки и отдыха |
| Заявка шин | Стратег | Склонность к риску по погоде |

**Медиа — особый случай.** Пресс-конференции можно передать пресс-атташе, но публичное лицо команды имеет значение: руководитель, который никогда не говорит сам, теряет в личной репутации, а она влияет на переговоры с пилотами. Делегировать можно, но не бесплатно.

**Доступность делегатов — часть прогрессии.** Делегировать область можно, только если в команде есть соответствующий сотрудник. В режиме B (новая команда) штат неполный, и первые сезоны игрок неизбежно ведёт всё сам. Как и с уровнями сетапа, возможность отойти от рутины покупается развитием команды.

**Связь с интерфейсом.** Настройки делегирования управляют объёмом входящих задач на главном экране: области в ручном режиме порождают задачи, делегированные — отчёты. Игрок, ведущий всё сам, видит двадцать пунктов между этапами; отдавший периферию — четыре. Самонастраивающаяся сложность без ползунка «казуальный режим».

**Пресеты при старте карьеры** (меняются в любой момент): «Полный контроль» — всё вручную. «Руководитель» — стратегические области вручную, операционные по указанию. «Только гонки» — всё на усмотрение, кроме уик-энда.

**Рабочее взаимопонимание.** Сотрудник, чьи предложения игрок регулярно принимает, со временем точнее угадывает предпочтения: его рекомендации сужаются, а решения ближе к тому, что выбрал бы игрок. Механика только положительная — за ручное управление и за отклонение советов штрафов нет.

**Архитектурное следствие (важно).** Делегат игрока и ИИ команды-соперника — это один и тот же код. Каждая система выставляет функцию вида:

```ts
decide<TContext, TDecision>(
  context: TContext,
  competence: DecisionMakerProfile,  // атрибуты сотрудника
  intent: Intent,                    // указание игрока или профиль ИИ-команды
  rng: Rng
): TDecision
```

Соперники вызывают её с параметрами своего персонала, делегат игрока — с параметрами его персонала. Одна реализация вместо двух, и качество ИИ соперников растёт вместе с качеством делегатов. Контракт `decide()` фиксируется в M1, до реализации первой системы принятия решений.

## 6. Интерфейс

### 6.1 Направление

Отправная точка — не «спортивный сайт», а **пит-уолл и инженерная телеметрия**: тёмная основа, плотные данные, монохромная база с одним цветом команды игрока как акцентом, много числовой информации, минимум декора. Ощущение — рабочий инструмент, за которым сидит человек, принимающий решения под давлением времени.

Что сознательно не делаем: карточки с одинаковым скруглением на всё подряд, градиентные заливки как украшение, ALL-CAPS-эйбрау над каждым заголовком, стрелки «→» в кнопках.

### 6.4 Экран сетапа

Девять ползунков, сгруппированных по трём уровням. У открытых — рекомендованный диапазон нарисован прямо на шкале, текущее значение внутри или вне него. У закрытых — значение видно (заводской пресет), ползунок неактивен, а в подсказке написано, что именно откроет уровень: «Требуется гоночный инженер уровня 60 или симулятор 2-го уровня». Это не только объяснение блокировки, но и способ показать игроку, куда расти.

Рядом — панель поведения болида: пять шкал (поворачиваемость на входе и выходе, стабильность на торможении, тяга, износ шин) с текущими отклонениями и цитатой пилота после последнего прогона. Кнопки автосетапа собраны в одну группу с явными названиями источника: «Прошлый год», «Совет инженера», «Заводской», «Как у напарника».

### 6.5 Делегирование в интерфейсе

Отдельного «экрана делегирования» нет. Переключатель режима стоит **на самом экране области** — в заголовке экрана сетапа, экрана разработки, экрана соцсетей. Игрок меняет режим там, где работает, а не в общих настройках. Сводная таблица всех областей доступна отдельно, для тех, кто хочет разложить всё сразу.

Делегированная область не выглядит заблокированной. Все данные на месте, все элементы управления видны; сверху добавляется строка с текущим указанием и результатом последнего решения сотрудника, а рядом — кнопка вмешаться. Разница между режимами читается спокойно и не создаёт ощущения запертой двери.

Главный экран разделяет входящее на две колонки: **решения** (области в ручном режиме, требуют действия) и **отчёты** (делегированные области, только для чтения, разворачиваются в обоснование). Соотношение колонок и есть визуальный индикатор того, сколько игрок взял на себя.

В гонке режим «предлагать с паузой» показывает предложение стратега модальным блоком с таймером: принять, изменить, отклонить. Таймер можно отключить в настройках.

### 6.6 Отображение оценок

Один компонент на всю игру. Игрок учит визуальный язык неопределённости один раз и дальше узнаёт его везде — от прогноза погоды до потенциала пилота.

Правила:

- **Оценка никогда не выглядит как точное число.** Если значение получено через `Estimate`, интервал показывается всегда, даже когда он узкий.
- Шкала с полосой: наиболее вероятное значение отмечено, интервал закрашен. Ширина полосы и есть основная передача уверенности.
- Дискретная подпись уверенности (низкая / средняя / высокая) дублирует ширину словами. Цветом уверенность не кодируется — цвет в интерфейсе занят командами и компаундами шин, и на нём нельзя строить смысл.
- Точные значения (очки, бюджет, круги) отображаются обычным способом и визуально отличаются от оценок. Разница между «знаю» и «предполагаю» должна читаться мгновенно.

**Подсказка обучает.** В раскрытии оценки перечислено, что сузит интервал: «Симулятор 2-го уровня, ещё одна длинная серия, аналитик выше 70». Так широкий интервал перестаёт быть просто раздражением и становится указателем, куда вкладываться. Это самый дешёвый способ объяснить игроку систему развития команды, не написав ни строчки туториала.

**Смещение не показывается никогда.** Команда с плохой корреляцией аэротрубы видит уверенные и узкие интервалы — просто неправильные. Обнаружить это можно только сравнив ожидания с результатом на трассе. Отдельный экран истории точности прогнозов («за сезон детали в среднем работали на 22% хуже расчёта») даёт игроку возможность самому докопаться до проблемы.

## 7. Дорожная карта

Каждая веха — самостоятельный кусок работы с проверяемым результатом. Порядок неслучаен: сначала работающая симуляция, потом обвязка вокруг неё.

### M0 · Каркас (2–3 дня работы агента)
Проект на Vite + TS strict, ESLint/Prettier, Vitest, структура папок из 3.2, дизайн-токены, базовые примитивы (кнопка, таблица, панель, тултип, диалог), роутинг, пустые экраны, i18n-каркас, тёмная тема.
**DoD:** приложение запускается, по всем разделам можно ходить, есть 3 примера компонентов в Storybook или на демо-странице.

### M1 · Домен и контент
Все доменные типы. Zod-схемы паков. Примитив `Estimate<T>` с функциями `observe()` и `refine()` (4.1) и контракт `decide()` для делегатов и ИИ-команд (5.19) — оба до реализации любой системы принятия решений. Пак данных: 22 трассы с профилями и SVG-геометрией, 11 команд с историей и контрактами, 22 пилота + 40 резервистов, 4 поставщика моторов, персонал. Генератор мира из пака: фиксированное стартовое состояние + скрытые величины от сида. Оба режима старта карьеры (A и B). Файлы баланса.
**DoD:** `createWorld(seed, pack, careerMode)` возвращает валидный мир; при разных сидах видимое стартовое состояние идентично, а скрытые величины различаются; схемы отвергают битые данные; есть тесты на обе ветки режима.

### M2 · Ядро гонки без интерфейса ⭐ критическая веха
Модель круга, шины, топливо, ERS, DRS, слипстрим, обгоны, пит-стопы, поломки, SC/VSC. Полная погодная модель из пяти величин с ветром по направлению (5.4). Эволюция трассы. Функция `simulateRace()`. CLI-скрипт для прогона.
**Калибровка обязательна:** отрыв топ-команды от аутсайдера ≈ 2–3%, разброс времён у пилота ≈ 0.2–0.4 с, деградация мягких ≈ 0.08–0.15 с/круг, число обгонов за гонку правдоподобно для профиля трассы, SC примерно в 40% гонок.
**DoD:** 1000 прогонов одной гонки дают распределение результатов, которое агент оформляет в отчёт `docs/calibration/M2.md`; один и тот же сид даёт идентичный результат; тесты на каждую подсистему.

### M3 · Визуализация гонки
Экран гонки из 6.3: таймингборд, карта трассы, лента событий, график разрывов, управление скоростью и паузой. Пока без вмешательства игрока — только просмотр.
**DoD:** гонку можно досмотреть от старта до финиша, всё, что произошло в симуляции, читается на экране.

### M4 · Управление гонкой и стратегия
Радио-команды, планирование стратегии до старта, изменение на ходу, окна пит-стопов, прогноз стратега, командные приказы, реакции пилотов. Первая реализация `decide()` на живой системе: делегирование стратегии и радио, режим «предлагать с паузой» (5.19).
**DoD:** решения игрока измеримо меняют исход — есть тест, где ранний undercut даёт позицию. Делегированная стратегия в среднем по 100 гонкам не хуже, чем на две десятые позиции, относительно ручной при том же уровне стратега.

### M5 · Полный уик-энд и сезон
FP1–3 с программами заездов (5.3), запас и заявка шин, квалификация с трафиком и выбором момента выезда, спринтовый формат, стартовая решётка с чистой и грязной стороной, штрафы. Разведка соперников с интервальной оценкой темпа (5.13). Календарь, начисление очков, обе таблицы чемпионата, межгоночные недели, промотка времени.
**DoD:** сезон из 22 этапов проходится целиком, таблицы сходятся, ничего не ломается на 22-й гонке. Пропуск практик измеримо ухудшает результат — есть тест.

### M6 · Болид и разработка
Компоненты, R&D-проекты с интервалами неопределённости, ATR и CFD как ресурсы, апгрейды и их валидация, философия сезона, надёжность. Пул компонентов силовой установки с плановыми штрафами и прогнозом ресурса (5.12). Предсезонные тесты и корреляция аэротрубы (5.17). Параллельная разработка следующего года. Сетап с тремя уровнями доступа и рекомендациями инженера (5.2).
**DoD:** за сезон болид игрока измеримо прогрессирует относительно поля; батч-прогон 5 сезонов показывает вменяемую динамику расстановки сил.

### M7 · Финансы
Бюджет, доходы и расходы, бюджетный потолок с расследованиями, спонсоры с KPI и переговорами, прогноз, экономические последствия аварий.
**DoD:** можно обанкротиться; можно нарушить потолок и получить санкции; экономика сходится по итогам сезона.

### M8 · Люди и рынок
Развитие пилотов, форма и мораль, персонал и департаменты, скаутинг, академия, трансферное окно, переговоры по контрактам, конкуренция за кадры с ИИ. Переток знаний при переманивании и садовый отпуск (5.15). Бюджет времени пилота и усталость персонала от календаря (5.16). Здоровье, травмы и роль резервного пилота (5.18).
**DoD:** межсезонье проходит осмысленно: пилоты меняют команды по внятной логике, топ-пилоты не подписываются в худшую команду без причины.

### M9 · Медиа
Пресс-конференции, интервью, оси репутации, соцсети с фанбазой и вовлечённостью, контент-план, кампании, кризисы, генератор новостей.
**DoD:** репутация влияет на спонсорские доходы и на готовность пилотов подписывать контракт — есть тест этой цепочки.

### M10 · Инфраструктура и долгая игра
Здания и их уровни, сроки строительства, корреляция аэротрубы, эффективность фабрики, загрузка департаментов, цели от владельцев команды и увольнение игрока.
**DoD:** есть проигрышное состояние; вложение в инфраструктуру окупается на горизонте 2–3 сезонов.

### M11 · ИИ, многосезонность, регламенты
Полноценные стратегии ИИ-команд, характеры, смена регламентов, реформы. Паддочная политика: голосования, технические директивы, протесты, отношения с FIA и партнёрами (5.14). Регенерация молодых пилотов, уход ветеранов, историческая статистика и рекорды.
**DoD:** батч-прогон 10 сезонов без участия игрока даёт правдоподобную историю: чемпионы меняются, есть доминирующие периоды, поле не вырождается.

### M12 · Сейвы, полировка, баланс
IndexedDB с миграциями, экспорт/импорт, автосейв, туториал и подсказки, пресеты делегирования при старте карьеры и сводная таблица областей (5.19), звуковое сопровождение (опционально), финальная балансировка на батч-прогонах, производительность (гонка не должна ронять FPS), доступность, адаптив, вторая локаль.
**DoD:** партию можно начать, отыграть 3 сезона, сохранить, закрыть браузер и продолжить.

## 8. Тестирование и балансировка

- **Юнит-тесты** на каждую формулу симуляции.
- **Тесты детерминизма**: сид + вход → фиксированный хеш результата. Ломается при непреднамеренном изменении логики.
- **Батч-прогоны**: скрипт `npm run sim:batch -- --seasons 100`, выдаёт статистику (распределение чемпионов, средние отрывы, частота SC, разброс стратегий) в CSV. Это главный инструмент баланса — глазами такое не настраивается.
- **Снапшоты сейвов** для проверки миграций.
- **Бюджет производительности**: полная гонка headless < 200 мс; отрисовка гонки — стабильные 60 FPS при ×15.

## 9. Риски

| Риск | Смягчение |
|---|---|
| Симуляция «на глаз» окажется неубедительной | M2 отдельной вехой с обязательным отчётом о калибровке до всякого UI |
| Объём фич уводит проект в бесконечность | Строгий порядок вех; игра играбельна уже после M5 |
| Интерфейс превращается в 40 таблиц | Один экран = один вопрос игрока. Если экран не отвечает на конкретный вопрос — он лишний |
| Экономика ломается на 5-м сезоне | Батч-прогоны с M7, а не в конце |
| Правовые претензии по именам | Вымышленный контент по умолчанию, паки — как механизм, а не как поставка |
| Гонка тормозит браузер | Симуляция в воркере с первого дня (M2), UI только рисует |

## 10. Зафиксированные решения

Принято владельцем проекта, менять только через ADR:

1. **Контент** — базовый пак вымышленный, с узнаваемыми архетипами вместо узнаваемых фамилий. Формат пака публичный, реалистичный вариант не входит в репозиторий.
2. **Старт карьеры** — оба режима, A и B (раздел 5.11), с раздельной балансировкой.
3. **Сетап** — 9 параметров, три уровня доступа, открываются качеством инженера и уровнем симулятора (раздел 5.2). Автосетапы по трассам, экспертный режим для принудительного снятия блокировок.
4. **Спринты** — входят в M5.
5. **Мир** — фиксированный. Одна и та же расстановка сил, состав пилотов и календарь в каждой партии.
6. **Делегирование** — три режима на область, полный ручной контроль сохраняется везде и всегда, единый контракт `decide()` для делегатов и ИИ (раздел 5.19).
7. **Неопределённость** — единый примитив `Estimate<T>` (4.1) и единый компонент отображения (6.6) для всех систем без исключения.

### Что означает «фиксированный мир» для реализации

Стартовое состояние берётся из пака детерминированно, без участия сида: одинаковые команды, характеристики болидов, контракты, финансы, календарь. Игрок из партии в партию узнаёт мир и учится в нём ориентироваться.

Сид при этом остаётся и управляет всем, что происходит **после** старта: скрытый потенциал молодых пилотов, склонность к травмам, результаты бросков в гонках, поломки, погода, поведение рынка, исходы R&D-проектов. Два человека с одним стартовым миром через три сезона окажутся в совершенно разных ситуациях.

Скрытые величины (`potential`, `growthRate`, `injuryProneness`) генерируются от сида в пределах диапазона, заданного в паке. Так талант молодого пилота нельзя выучить наизусть, а расстановку сил на старте — можно.

## 11. Открытые вопросы (не блокируют M1)

1. **Проигрышное состояние в режиме A**: увольнение игрока с окончанием партии или предложение перейти в другую команду?
2. **Уровень детализации трасс на карте**: 3 сектора или мини-сектора по 8–12 точек? Влияет на точность отображения разрывов и на объём работы по геометрии в M1.
3. **Академия и младшие серии**: полноценная симуляция F2/F3 или абстрактный скаутинг с числовыми отчётами? Первое дороже примерно на веху.
4. **Интерактивность пресс-конференций**: выбор из вариантов или свободный ввод с оценкой тона?
